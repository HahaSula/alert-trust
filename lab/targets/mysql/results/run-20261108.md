## 摘要
- 環境：mariadb:11.4、prom/mysqld-exporter:v0.21.0、prom/prometheus:v3.13.5，scrape_interval 5s、scrape_timeout 4s。
- b：資料庫停機時 up=1、mysql_up=0，collector_success 整組消失（不是變 0），mysql_* 只剩 mysql_up。
  scrape_duration_seconds 約 3.75s，等於 scrape_timeout 減 --timeout-offset（0.25s），連線一直等到 context 取消。
- c：exporter 停機時 `mysql_up != 1` 與 `mysql_up == 0` 都回傳空；`up{job="mysql"} == 0` 與 `absent(mysql_up)` 會成立。
- d1：MariaDB 收回 SLAVE MONITOR，collect.slave_status=0（非 replica 時本來就沒有 mysql_slave_status_* 系列，所以看不出差別）。
- d2：收回 PROCESS，innodb_cmp、innodb_cmpmem、innodb_metrics 變 0，mysql_* 系列 1150 → 1060；
  rseg_history_len 消失，awesome 的 history_len 規則回傳空。processlist 仍回報成功。
- 啟用 --collect.heartbeat 但沒有 heartbeat 表：collect.heartbeat=0，沒有 heartbeat 系列。
- e：沒有 Galera 的 MariaDB 也輸出 mysql_global_status_wsrep_ready=0，mixin/awesome 的 `wsrep_ready != 1` 會誤報。
